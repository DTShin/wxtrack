## 二、数据管线 (Pipeline) 详解

### 2.1 管线入口

统一入口脚本：`bash scripts/run_pipeline.sh <模式>`

支持 4 种模式：

| 模式 | 执行脚本链 | 触发时机 | 用途 |
|------|-----------|---------|------|
| `forecast` | collect_forecast → predict → gen_dashboard → push_dashboard | **每小时 :07 自动** | 采集预报 + 研判 + 更新网页 |
| `obs` | collect_obs | **每日 11:05 UTC 自动** | 采集昨日实测 |
| `stats` | stats_bias → gen_vault → gen_dashboard → push_dashboard | **每日 11:15 UTC 自动** | 偏差统计 + 知识库 + 更新网页 |
| `health` | healthcheck | **每日 04:00 UTC 自动** | 健康检查 |

### 2.2 各模式详细流程

#### 模式 `forecast`（每小时执行）

```
┌──────────────────────┐
│ collect_forecast.py  │  调用 Open-Meteo API 批量获取 12 个模型预报
│                      │  + meteoblue 网页抓取
│          │           │  写入 forecast_snapshot 表（UNIQUE约束防重复）
└──────────┼───────────┘
           ▼
┌──────────────────────┐
│    predict.py        │  读取各模型最新快照 → 应用 30 天偏差修正 →
│                      │  取中位数 → 生成综合研判预报
│          │           │  输出: vault/00_MOC/综合研判预报.md
└──────────┼───────────┘
           ▼
┌──────────────────────┐
│  gen_dashboard.py    │  聚合所有数据 → 生成 dashboard/data.json
│                      │  包含: 48城×3天预测、全模型详情、偏差、演化
└──────────┼───────────┘
           ▼
┌──────────────────────┐
│  push_dashboard.sh   │  git add + commit + push → GitHub Pages
│                      │  仅在有数据变更时推送（避免空提交）
└──────────────────────┘
```

#### 模式 `obs`（每日一次）

```
┌──────────────────────┐
│   collect_obs.py     │  T+1 原则: 统计所有城市"昨日"完整本地日
│                      │  调用 aviationweather.gov METAR API（48h窗口）
│          │           │  从逐时观测中提取当日最高温
│          │           │  写入 obs_tmax 表
└──────────────────────┘
```

#### 模式 `stats`（每日一次）

```
┌──────────────────────┐
│   stats_bias.py      │  配对 forecast_snapshot 与 obs_tmax
│                      │  计算每个 city×model×lead 的 bias/MAE/RMSE
│          │           │  写入 bias_stat 表（30天滚动 + 全期窗口）
└──────────┼───────────┘
           ▼
┌──────────────────────┐
│   gen_vault.py       │  生成 Obsidian 知识库（约 70+ Markdown 文件）
│                      │  Home.md / 城市索引 / 48城详情 / 13模型页 /
│                      │  日报 / 模型榜 / 修正建议
└──────────┼───────────┘
           ▼
┌──────────────────────┐
│  gen_dashboard.py    │  同 forecast 模式，更新 data.json
└──────────┼───────────┘
           ▼
┌──────────────────────┐
│  push_dashboard.sh   │  推送更新到 GitHub Pages
└──────────────────────┘
```

## 三、数据存储结构

### 3.1 SQLite 数据库 (`/workspace/data/wxtrack.db`)

#### forecast_snapshot（预报快照表）

| 字段 | 类型 | 说明 |
|------|------|------|
| city | TEXT | ICAO 代码 |
| model | TEXT | 模型 ID（如 ecmwf_ifs025） |
| target_date | TEXT | 预报目标日期 |
| lead_days | INT | 提前天数（0=当天, 1=明天...） |
| tmax | REAL | 预报最高温 °C（NULL=无数据） |
| run_slot | TEXT | 采集槽位（如 2026-07-23T08:30Z） |
| collected_at | TEXT | 采集时间戳 |
| source | TEXT | 数据来源（open-meteo / meteoblue） |

> **唯一约束**: `(city, model, target_date, run_slot)` — 同一槽位不重复记录

#### obs_tmax（实测最高温表）

| 字段 | 类型 | 说明 |
|------|------|------|
| city | TEXT | ICAO 代码 |
| local_date | TEXT | 本地日期 |
| tmax_metar | REAL | METAR 实测最高温 |
| tmax_wu | REAL | wunderground 实测（当前暂停） |
| tmax_final | REAL | 最终采用值 |
| src_final | TEXT | 来源标记（metar/wu） |
| conflict | INT | METAR vs WU 冲突标记 |

> **唯一约束**: `(city, local_date)`

#### bias_stat（偏差统计表）

| 字段 | 类型 | 说明 |
|------|------|------|
| stat_date | TEXT | 统计日期 |
| city | TEXT | ICAO |
| model | TEXT | 模型 ID |
| lead_days | INT | 提前天数 |
| n | INT | 配对样本数 |
| bias | REAL | 平均偏差 |
| mae | REAL | 平均绝对误差 |
| rmse | REAL | 均方根误差 |
| window_days | INT | 滚动窗口（30 或 99999=全期） |

> **唯一约束**: `(stat_date, city, model, lead_days, window_days)`

### 3.2 配置文件

| 文件 | 内容 |
|------|------|
| `config/cities.yaml` | 48 城市（ICAO、中文名、时区、坐标、排序） |
| `config/models.yaml` | 13 模型（ID、标签、覆盖范围、数据来源） |
| `config/smartsheet.yaml` | 腾讯文档智能表格映射 |
| `config/meteoblue_urls.yaml` | meteoblue 城市页面 slug 缓存 |

### 4.3 index.html 前端特性

| 功能 | 说明 |
|------|------|
| **总览表** | 48 城 × 3 天预测，按时区排序，支持列排序 |
| **搜索过滤** | 输入城市名或 ICAO 即时筛选 |
| **置信度图标** | 🟢高(≤1°C) 🟡中(≤2.5°C) 🔴低(>2.5°C) |
| **°C/°F 切换** | 一键切换温度单位 |
| **暗色模式** | 深色主题切换 |
| **城市详情抽屉** | 点击行展开：3 天预测卡、全模型预报表、实测历史、偏差统计、快照演化图 |
| **Polymarket 链接** | D0/D+1/D+2 跳转预测市场（已验证市场标 ✓） |
| **自动刷新** | 每 5 分钟 fetch data.json 更新 |
| **高温警报** | ≥38°C 行高亮 + 红色标签 |

### 4.4 推送脚本工作方式

```bash
# push_dashboard.sh 核心逻辑:
1. 读取 GitHub PAT 令牌（/workspace/.secrets/github_token）
2. 配置 git remote（带 OAuth2 认证）
3. git add -A  →  检查是否有实际变更
4. 无变更: 跳过推送（避免空提交）
5. 有变更: git commit → git push origin main
6. GitHub Pages 自动部署（通常 <1 分钟）
```

### 4.5 GitHub Pages 访问地址

> **https://dtshin.github.io/weather-dashboard/**

任何联网设备均可访问，无需安装任何软件。

### 4.6 推送频率

- 每小时一次（forecast 模式，跟随预报采集）
- 每日一次额外推送（stats 模式，跟随偏差统计更新）
- 总计：约 25 次/天

### 5.2 更新方式

- `gen_vault.py` 每天运行一次（stats 模式）
- **幂等覆盖写**：每次重新生成所有 Markdown 文件
- 通过 Obsidian 的 `[[双向链接]]` 关联城市 ↔ 模型 ↔ 日报

### 5.3 在 Obsidian 中使用

1. 在本地电脑安装 [Obsidian](https://obsidian.md/)
2. 将 `/workspace/vault/` 目录复制到本地，或用 Git 同步
3. 在 Obsidian 中打开该目录作为 Vault
4. 即可查看双向链接、图谱视图、搜索等功能

## 十一、故障排查

### Dashboard 页面不更新？

1. 检查 `push_dashboard.sh` 执行日志
2. 确认 GitHub Token 未过期
3. 手动执行 `bash scripts/push_dashboard.sh` 查看错误
4. GitHub Pages 部署通常有 1-2 分钟延迟

### 定时任务没有新数据？

1. 检查独立沙箱是否能访问 `github.com/DTShin/wxtrack`
2. 检查 Open-Meteo API 是否可用: `curl https://api.open-meteo.com/v1/forecast`
3. 运行 `python3 scripts/healthcheck.py` 查看诊断

### meteoblue 抓取失败？

- meteoblue 网页结构可能改版，检查 `scrape_meteoblue.py` 的 CSS 选择器
- 部分城市搜索 API 可能未返回结果
- meteoblue 失败不影响其他 12 个模型的数据采集

### 数据积累不足？

- 偏差统计需要 ≥3 天配对数据才有参考价值
- 当前只有 2 天数据，预计 7-10 天后偏差值趋于稳定
